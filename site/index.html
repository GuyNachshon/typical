Calibration

JevBench disclosure. JevBench numbers are a public-subset run against fstandhartinger/jevbench v1.2.1 (72 standard / 48 easy / 111 hard public ids), not a submitted or ranked leaderboard entry (the leaderboard requires ≥95% coverage including 146 non-public judge items). Probabilities are the head's softmax conditioned on non-∅ (mean p_null ≈ .03). Latency is in-process on one H100, one decision at a time, model load excluded. Option order is the harness's label order; a reversed-order control on a related checkpoint moved standard accuracy ±4 points, larger than the differences between our own checkpoints. Chance/majority baselines are .311 standard / .284 easy / .336 hard (n = 72 standard, SE ≈ .058) — the hard tier of both released models is within 1 SE of chance.

How it works

Choice

Pick one candidate from a set you define at runtime; returns a probability for every option.

Noul

A yes/no read on the same state — the one query type that is exact and order-invariant.

Score

An ordered level, 0 through N, with an expected value under the candidates.

from typical import Typical

m = Typical.from_pretrained("OzLabs/typical-small")
m.choice(state, "What does the customer want?", ["refund", "replacement", "repair"])
m.noul(state, "Is the order still under warranty?")
m.score(state, "How urgent is this ticket?", ["0", "1", "2", "3"])

Typical is an open family of small decision models. Give it a text state and a typed question — Choice over candidates you define at runtime, Noul (yes/no), or Score (ordered levels) — and it returns a probability for every candidate plus an explicit ∅ in one forward pass: no generation, no parsing, 45 ms per decision on one H100 and a few milliseconds per extra question on the same state. It is not an LLM replacement and not a knowledge model: it decides from the text you give it (≤1k tokens), it does not plan, compute, or reason over long documents, and on hard multi-step workflow judgments it is still at chance. Weights (1.7B, 4B) and inference code are open on Hugging Face.

What does not work

  • Doom — mostly shoots, enemy or no enemy.
  • Drive — never once changes lanes.
  • Compaction — no usable keep/drop threshold.
  • Level-7 composition — temporal, units, expected value, trade-off: at chance.

What this isn't

Short states, literal rules, bounded candidate sets. No arithmetic, no timezones, no trade-offs, no long policies, no vision. The hard tier is at chance and over-confident; Choice is order-robust, not order-invariant. Here is the list.

  • We do not claim to be faster, better, or cheaper than Jev or any hosted system — we have no apples-to-apples run and JevBench is unranked here.
  • We do not do vision, audio, real-time control, game-playing skill, or planning/lookahead. Text-only, one forward pass, no search.
  • We are not a knowledge model or a reasoner: MMLU-Pro among-K .34 / .46; level-7 composition (temporal, units, expected value, trade-off) is at chance. We do not do arithmetic, timezones, or trade-offs.
  • We do not read long documents: trained at ≤1,024-token states; JevBench long-policy items and multi-thousand-token states are out of distribution.
  • We do not claim "any label set, any domain" works equally well: some label sets regress against their untyped control (CLINC −4, TREC-fine −10), and held-out rubric styles drop 4–6 points.
  • We do not claim exact order-invariance for Choice, or exact IIA. Only Noul (yes/no) is exact; Choice is order-robust (mean-max Δp .01–.08), and adding an irrelevant candidate can move log-odds .09–.22.
  • We do not claim OOD calibration or hard-tier competence: both released models are at chance on the JevBench hard tier (Brier .79 / .77).
  • We have not released training code — only inference/ is public; a training-code release may follow.
  • Licence: see the model card's licence section. The training mix includes sources with non-commercial or undeclared licences (ANLI is CC BY-NC 4.0); only inference/ is public today.

Get started

pip install -r inference/requirements.txt, six lines of Python, weights from Hugging Face. state is a string or a dict; candidates are whatever you pass.

pip install -r inference/requirements.txt
from typical import Typical

m = Typical.from_pretrained("OzLabs/typical-small", device="auto")  # or "typical-small-preview" / "typical-medium"

# K-way choice over a fixed label set -> {label: p, ...} + p_null
m.choice(state, "What does the customer want?", ["refund", "replacement", "repair"])

# Yes/no -> P(yes)
m.noul(state, "Is the order still under warranty?")

# Ordinal levels -> {level: p, ...} + p_null + expected (E[index] under the candidates)
m.score(state, "How urgent is this ticket?", ["0", "1", "2", "3"])

# Full JevBench-style decide() -- mirrors pcdm_jev.decider.PCDMDecider.decide exactly,
# including the runtime block (latency, p_null, truncation flags).
probs, runtime = m.decide(
    state,
    {"type": "choice", "instructions": "What does the customer want?",
     "criteria": {"refund": "money back", "replacement": "a new item shipped"}},
    ["refund", "replacement"],
)
